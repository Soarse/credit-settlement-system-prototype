# 零售信贷资金方计费结算系统 · 可模拟前端工程

依据《零售信贷资金方计费结算系统 产品设计文档 PRD v0.3》实现的**可实际操作的前端模拟工程**。
零依赖、无构建步骤 —— 双击 `index.html` 即可运行。

业务流程设计详见 [`docs/信贷资方结算系统_30个流程与模块关系说明.md`](docs/信贷资方结算系统_30个流程与模块关系说明.md)。原型右上角“流程引导”包含 30 个标准流程和 2 个综合演练，并按七类业务生命周期分区展示。

---

## 一、如何运行

**方式 A（最简单）**：双击 `index.html`，用 Chrome / Edge 打开。

**方式 B（推荐，避免个别浏览器的 file:// 限制）**：在工程根目录起一个静态服务器

```bash
python -m http.server 8080     # 然后访问 http://localhost:8080
# 或
npx serve .
```

> 全部数据在浏览器内存中生成与运算，**刷新页面即回到初始状态**；左下角「重置模拟数据」可随时恢复。

## 二、初始状态

工程启动时自动跑完一遍真实链路，落在这样一个状态：

| 账期 | 状态 |
|---|---|
| **2026-03** | 已封账 → 已出账 → 已推送 → 资金方已确认 → 已开票 → 已结算（应付走付款指令、应收走收款认领）→ 回单已回写 → 五级勾稽全绿 |
| **2026-04** | 费用流水已就绪，**待封账**（留给使用者亲手驱动全流程）；另埋有 **3 条上游漏推事件**，供演示 12.1.5 核对与回补 |
| **2026-05** | 2 条事件停在待处理队列（演示「事件积压阻断封账」） |

数据规模（固定随机种子，每次打开完全一致）：

- 业务事件 **≈ 2,870 条**（放款 / 还款 / 日终余额快照 / 撤销 / 退款 / 异常事件）
- 费用流水 **≈ 2,640 条**，基数快照 **≈ 2,630 条**
- 借据 89 笔、账单 6 张、结算单 5 张、银行回单 9 张、银行入账流水 5 笔（3 已核销 / 2 挂账）、开票申请 6 张（均已开票）、争议单 3 张（1 张已超 SLA）
- 资损监控六项指标中，**差异老化 26 天已越 P1 阈值**（涉及 16.0 万元）、**事件积压 2 条**接近阈值，其余四项为 0 —— 告警中心初始 6 条未关闭告警，可直接演示关闭闭环

## 四、推荐体验路径

0. **接入 SOP（5 天）** ← 建议从这里开始
   用「晟元租赁 P000045（待准入）」发起接入任务，完整走一遍：
   **D1 条款拆解表 + 三方会签 → D2 主数据与规则配置 → D3 人工算例逐笔比对 → D4 分级审批 → D5 发布上线**。
   每天一个卡点，未通过时「进入下一天」按钮直接禁用；D3 把人工核算金额改成一个对不上的数，会看到「无法解释的差异 → 阻断，退回 D1 重新确认口径」。
0b. **资金方主数据 → ＋ 新建资金方**
   填一个与现有机构重复的统一社会信用代码，V-P01 实时拦截并指出与谁重复；新增银行账户后<b>切换角色</b>复核，体验 V-P03 双人复核与 T+1 冷静期；协议保存时 V-P05 / V-P06 实时校验，终止协议时 V-P07 检查未结清账单。
1. **规则中心 → 协议版本时间轴**（`AG202601000012`）
   看 V01/V02 的左闭右开时间切片、区间不变式校验，并用页面底部的「**版本路由试验器**」输入任意 `occur_date` 验证路由结果。
2. **规则中心 → 规则配置向导**
   6 步配一条规则，右侧「**规则自然语言预览**」实时把 JSON 翻译成人话，并逐条跑 V-R01~R09 校验；
   第 4 步的「**累进 vs 超额**」对比卡片会算出同一基数下 80 万的差额（PRD 风险 R8）。
3. **规则中心 → 试算**
   用 4 月真实事件对比现行版本与 V03 草稿，输出差额报告；**未试算不得发布**（V-R09）。发布时展示原子发布的 7 个步骤。
3b. **计费引擎 → 日度核算调度**
   一天中 7 个时段的调度编排（点「模拟执行 T+1 日度核算」可逐段推进）、当日核算结果与按资金方拆分、
   **5 条日度异常识别规则实时求值**（日增突变 / 事件积压 / 快照缺失 / 冲正率 / 零费用协议），
   以及近 30 日日增费用趋势柱状图（可按资金方切换，环比突变自动标记）。这是「出账 5 天 → 3 小时」的技术支点。
4. **计费引擎 → 费用流水**
   点任意一条流水，看**三向引用**（业务事件 / 规则版本快照 / 基数快照）与完整验算过程（含价税倒轧）。
5. **计费引擎 → 冲正工作台**
   选一条流水注入反向事件；把冲正金额调大到超过剩余可冲金额，会看到「**重复冲正拦截 + P0 告警**」（S-06）。
5c. **计费引擎 → 事件核对与回补**（PRD 12.1.5 / 10.2）
   初始数据里埋了一个缺口：上游 4 月有 3 笔 P000012 放款事件<b>没送达</b>。
   这种缺口<b>不会自己暴露</b> —— 账单照样出、勾稽照样平，因为系统压根不知道那几条事件存在过。
   本页按<b>日期 × 资金方 × 事件类型</b>与上游核对笔数，把缺口定位到具体哪天哪家哪类；
   点「执行回补」拉取该范围上游全量，951 条里幂等拦截 948 条、补齐 3 条，补齐后立即进入计费并产生费用流水。
   <b>再点一次回补，951 条全部被幂等拦截</b> —— 正因为重复执行零风险，回补才敢做成「有疑就拉一次」。
5b. **账单中心 → 预出账**（PRD 7.2）
   封账前先走这一步。预出账<b>不是「提前出账」，是把出账日的体检提前到账期中</b> ——
   真到了出账日才发现缺 8 天快照，补数 + 重算 + 复核根本压不进 3 小时。
   把「预览截至业务日」拖到 04-10 / 04-20 / 04-30，看同一账期在不同时点的样子：
   六个出账组合的三项构成实时重算，<b>全月落点给的是区间不是一个数</b>
   （线性外推 vs 同期比对两种口径并列，页面直说各自什么时候准、什么时候不准；
   两法的差本身就是信号 —— 差得大说明本期月内节奏变了）。
   <b>「现在就能修的事」独立成栏</b>，每条直接跳到能修的地方（缺快照 → 核对与回补、调整项未审批 → 调整项）。
   三条硬约束在页面上可验证：<b>不落库</b>（反复跑一百次不产生账单、不回写 <code>fee_flow.bill_no</code>）、
   <b>同源</b>（与正式出账共用 billPreCheck 与构造逻辑，V-B01 封账 / V-B02 恒等两条标为「出账时判」）、
   <b>留档可比</b> —— 点「留档本次预出账」存快照，走完封账出账再回来「与账单比对」：
   <b>在账期末（04-30）留的快照，与 6 张正式账单逐张分文不差</b>；账期中留的快照差在哪里，
   就是那之后新发生的费用与调整项，差额可解释，不是口径漂移。
6. **账单中心 → 出账工作台**
   对 2026-04 依次执行 **封账 → 出账**；未封账直接出账会被 V-B01 阻断，校验面板逐条列出 V-B01~B10。
6b. **账单中心 → 出账日历**（PRD 7.2.2 / 7.4.2）
   五家资金方的封账日 / 出账日 / 确认截止 / 结算日排在一张月历上，可翻月，点任一里程碑看当日排期。
   <b>PRD 7.2.2 的示例可在页面直接验证</b>：2026-04 账期封账 04-30，出账日本应为 05-01，
   但 5/1–5/5 是劳动节，按 NEXT_WORKDAY 顺延至 <b>05-06</b>；确认截止随之 <b>05-11</b>、结算日 <b>05-14</b> ——
   顺延是<b>逐级</b>的，出账被假期推后，确认期不会被挤掉。
   下方「超期未确认处理」逐协议列出策略与<b>条款依据</b>：华信 / 星辰 / 瑞通有明确条款走「超期默认确认」，
   长安 / 安泰没有条款则缺省「挂起并升级」。把某张已推送账单的确认截止日改早，点「执行超期未确认策略」，
   两类账单会走两条不同的路 —— 一张视同确认并自动开票，一张挂起、升级、<b>不得进入结算</b>。
7. **账单中心 → 账单详情**
   四级下钻：账单 → 明细 → 费用流水 → 事件/快照；账单构成用台账形式呈现「本期费用 + 调整项 + 上期结转」。
7b. **审批中心 · 待办**（侧边栏「横向支撑」）
   所有分级审批的统一入口。初始有 2 张在途审批单（协商减免、账户变更）。要点：
   审批链由「业务类型 + 影响金额 + 风险标记」<b>自动生成，不可人工指定</b>；
   待办按<b>当前角色</b>过滤（切换右上角角色能看到不同待办）；
   敏感操作需<b>二次身份验证</b>（页面直接给出模拟验证码）；
   <b>发起人不得审批自己提交的单据</b>——发起人恰为第一级时该级视同已完成，单级链会自动升级一级；
   <b>驳回会把业务单据状态原路回退</b>（如规则版本回到草稿、结算单回到待结算）。
7c. **账单中心 → 发票管理**（PRD 7.8 / 决策 D-08）
   初始 3 月 6 张账单已各开出一张发票，可看到<b>购销方由账单方向决定</b>（应收＝平台开给资金方，应付＝资金方开给平台）、
   带<b>税收分类编码</b>的发票明细行、价税三段恒等（税额倒轧）。
   点「轧差与开票的关系」卡片：华信银行两张发票各按<b>全额</b>开具（33,350.00 / 22,077.55），银行只划转净额 11,272.45 ——
   <b>开票合计与实际划转本就不应相等</b>，这是 7.8.4 唯一要讲清的事。
   驱动 4 月出账并确认 P000012 应收账单，会<b>自动</b>拆成「1 张蓝票 + 2 张红字发票」：
   两笔 ≥ 1,000 元的跨期负调整走红字冲回原发票，那笔 −300 元低于起开线直接并入蓝票净额，
   系统把<b>判定理由写进申请单</b>而不是留给运营每次自己拍；恒等校验 123,083.00 + (−15,862.00) = 107,221.00。
   申请单可走完「提交发票系统 → 开票失败告警 → 修正重提 → 开票成功回写发票代码/号码/PDF」的完整状态机。
7d. **账单中心 → 争议工作台**（PRD 7.7）
   初始 3 张争议单，按 <b>SLA 剩余时间倒排序</b>：长安信托「基数不符」已超 T+5（红色超期），
   星辰消金「费率适用错误」剩 3 个工作日，华信银行「冲正未体现」刚提出待受理。
   点「处理」→ <b>执行自动定位</b>，系统按争议类型走对应的定位路径拉数生成<b>核查包</b>：
   费率争议会指出「差额来自阶梯月末找平，不是费率错误」；冲正争议会证明「冲正已体现，只是按 D-06 落在下期调整项里」；
   重复计费争议会给出幂等键判定与网关拦截记录。<b>没有核查包不得出结论</b>——结论必须建立在可出示的判定过程上。
   然后走三分支之一：<b>维持原账单</b>（生成带追溯链路的说明材料）、<b>己方有误</b>（按差额生成调整项计入下期，走审批）、
   <b>需重算</b>（发起范围重算，差额再计入调整项）。资金方不认可会退回重新核查，认可才闭环。
   点「执行 SLA 超时升级检查」可看到 T+3 升财务负责人、T+5 升业务负责人并进入月度质量复盘 —— SLA <b>按工作日计</b>，不因为「在等对方回复」而暂停。
8. **结算中心 → 结算详情**
   看**轧差计算过程**与 10 项资金安全控制（FC-01~FC-10）；试着点「模拟：状态未知」触发 P0。
   注意<b>应收与应付走两条不同的路</b>：应付方向审批通过即下发付款指令；
   应收方向不发指令，结算单停在「<b>待收款</b>」，等资金方划款到账后由收款认领核销。
8a. **结算中心 → 支付异常**（PRD 8.4.3 / 8.4.4 / 8.5）
   付款不是二值的。在结算详情页对一张<b>应付</b>结算单点三个模拟入口，可分别走完三条旁支：
   · <b>状态未知</b> —— 末笔通道无明确结果，转<b>递增主动查询</b>（30 秒 / 2 分钟 / 10 分钟 / 30 分钟）；
     累计 2 小时仍未明确即置 UNKNOWN + P0。此时界面上<b>没有「重试」按钮</b>——这不是遗漏，是设计；
     只有「人工确认实际已成功（补记流水与回单）」和「人工确认实际未出账（转可重试）」两个出口，且需财务复核及以上角色。
   · <b>部分成功</b> —— 要做两件并列的事：对失败那几笔<b>生成补发指令</b>（结算单不拆、序号续号、记录补发来源），
     以及把本期确实没收到的钱<b>结转进下期账单的第三项</b>。补发解决「钱还要付」，结转解决「账要对得上」。
   · <b>退票</b> —— 钱出去过又回来了，所以要做三件事：结算单置退票、<b>账单回退至已确认</b>并解绑结算单、
     <b>收款账户冻结并移出白名单</b>。此时点「重新结算」会被拦住，提示先去主数据完成账户变更与双人复核（FC-01）。
   页面同时给出<b>重试策略矩阵</b>（哪些状态可重试、哪些禁止、各自的理由）与结算状态机的后续动作对照。
8b. **结算中心 → 收款认领**
   应收方向的资金闭环。初始有 5 笔银行入账流水：3 笔已按<b>规则 1 / 2 / 3</b> 匹配并核销
   （其中容差那笔少到 0.01 元，可看到认领人 ≠ 复核人的留痕），2 笔<b>挂账</b>（其中 1 笔已超 3 个工作日触发告警）。
   点挂账笔的「处理」，可看到<b>四级匹配规则逐条给出未命中原因</b>，并三选一：认领到待收款结算单 / 标记为非本系统款项 / 原路退回。
   想完整体验：先驱动 4 月出账结算（步骤 6~8），应收结算单进入「待收款」后，
   用「模拟资金方划款到账」分别演示<b>规则 1 备注含单号、规则 2 金额精确、规则 3 容差、金额对不上→挂账、非白名单付款方→挂账</b>；
   认领后<b>切换角色</b>才能复核（认领人不得自复核），复核通过即核销 —— 生成结算流水与回单，
   结算单转已完成、账单转已结算，<b>五级勾稽 L4→L5 在收款方向才有落点</b>。
9. **对账中心 → 五级勾稽看板**
   等式 A~N 实时求值；差异工作台看「**自动定位分析**」核查包。
9b. **对账中心 → 外部对账**
   与资金方的完整文件交换闭环，四步可真实操作：
   **① 导出我方明细 CSV**（UTF-8 含 BOM / CRLF / 尾行 `#TOTAL` 校验行，文件名遵循 `{类型}_{partner_no}_{yyyyMMdd}_{seq}.csv`）
   → **② 上传资金方回传文件**（可用真实 CSV 上传，也可「生成模拟回传文件」下载后再上传，或「一键载入模拟回传」）
   → **③ 逐笔匹配**（优先按费用流水号，未命中时以「借据号 + 计费项」兜底；输出一致 / 容差核销 / 金额不符 / 己方多 / 对方多五类结果与匹配率、差异率）
   → **④ 生成差异单**（≤ 0.05 元自动核销并计入容差累计，超月度 100 元阈值触发口径复核；> 0.05 元逐条生成差异单，携带**自动定位核查包**进入差异工作台闭环）。
   点任一差异行的「定位」，可看到「事件存在性 → 基数一致性 → 费率差异」的逐层判定与疑因、证据、处理建议。
9c. **对账中心 → 资损监控指标**（PRD 9.6）
   六个指标不是「看板上的数字」，而是<b>资损的六个入口</b>：勾稽不平、事件未计费积压、冲正率、
   差异老化、结算失败率、回单缺失。每个都带阈值与级别，<b>数值从真实状态实时算出</b>（不是随机造的），
   卡内嵌 30 个业务日迷你趋势，点任一卡切换主趋势图 —— 图上有<b>阈值参考线</b>，越线的柱带 ▲ 标记，
   图下方另附表格视图。初始状态下「差异老化 26 天」已越 P1 阈值（涉及 16.0 万元）、「事件积压 2 条」接近阈值。
   点「立即扫描指标」把越线指标推成告警；<b>重复扫描不刷屏</b>，同一指标只累加次数（×N）。
9d. **告警中心 → 告警关闭闭环**（PRD 9.6.2）
   告警的价值不在「响」，而在<b>关掉</b>。每条告警必须走完「产生 → 处理 → 填写处理方式与说明 → 关闭」，
   四种关闭方式（已修复 / 误报 / 已知风险·接受 / 暂不处理）在月度质量复盘时含义完全不同。
   硬约束三条：<b>说明不得少于 4 个字</b>；<b>P0 不允许「暂不处理」</b>；
   <b>指标未回落不得以「已修复」关闭</b>（详情弹窗会直接显示关联指标当前值与阈值）。
   P2 / P3 可批量关闭，P0 / P1 必须逐条处理。已关闭的可<b>重新打开</b>并计数，全过程写留痕。
   反向也成立：把差异单全部闭环后再扫描，老化指标回落，对应告警<b>自动关闭</b>（处理方式记为「指标已回落」）。
10. **全链路追溯**
    输入任一回单号 / 结算单号 / 账单号 / 流水号 / 借据号 / 事件 ID，展开追溯树（反向 6 层）。
11. **右上角切换角色**
    切到「审计（只读）」后所有写操作按钮禁用 —— 对应 PRD 第 14 章权限矩阵。

## 六、实现深度说明

这不是静态页面拼图，计算逻辑是**真的**：

| 能力 | 实现 |
|---|---|
| 五要素抽象 | 触发事件 / 计费对象 / 计费基数 / 费率模型 / 冲正机制，全部由 JSON 规则驱动，无按费种硬编码 |
| 费率模型 | `FIXED_RATIO` / `FIXED_AMOUNT` / `DAILY_RATE`（基准 360，算头不算尾） / `TIER_PROGRESSIVE` / `TIER_FLAT` |
| 精度 | 单条流水四舍五入至分 → 再汇总；价税分离**倒轧**保证三段恒等；避免浮点累加漂移 |
| 版本化 | `[effective_date, expiry_date)` 左闭右开 + 按 `occur_date` 路由 + 区间不重叠不留空洞校验 |
| 幂等 | `event_id + charge_item_no + rule_version` 唯一键 |
| 冲正 | 红冲式反向流水 + 按比例部分冲正 + 累计校验硬拦截 + 跨账期调整项（D-06） |
| 阶梯 | 增量法逐笔计费 + `EV_PERIOD_CLOSE` 找平；撤销回退累计基数并重新找平 |
| 试算/重算 | 与正式计费**共用同一计算内核**，仅输出目标不同；重算走影子表 → 差异比对 → 审批 → 红冲+补记原子生效 |
| 五级勾稽 | 等式 A~N 全部按 PRD 9.1.2 实现并实时求值，另含状态一致性 S-01~S-08 |
| 主数据写入 | 资金方 / 账户 / 开票 / 协议全部可新建与编辑；V-P01~V-P08 实时校验并直接控制按钮可用性；准入与协议状态机可流转；每次变更写 config_change_log 前后快照 |
| 接入 SOP | D1~D5 五段式向导，每天一个强制卡点：条款拆解表三方会签、V-R01~R08 全通过、逐笔比对差异为 0（或 ≤0.05 容差）、分级审批全通过、发布 + 账期日历 + 首日监控 |
| 审批流 | 审批单为一等实体；链路按「业务类型 + 影响金额 + 风险标记」自动分级（规则发布 / 重算 / 结算 / 调整项 / 账户 / 作废）；逐级串行、任一级驳回即回退业务状态；发起人不得自批（自动升级）；敏感操作二次验证；全程留痕 |
| 日度核算 | 7 段调度编排可模拟执行；当日快照到齐 / 事件接入 / 流水生成按资金方拆分；AN-1~AN-5 五条异常规则对选定业务日实时求值；30 日趋势图按资金方可切换 |
| 发票与税务 | 价税分离三段式 + 倒轧；账单确认<b>自动</b>生成开票申请；购销方按方向判定；带税收分类编码的明细行；开票申请状态机（待提交 → 已提交 → 已开票／失败 → 可重提）；V-I01~V-I06 开票前置校验；红蓝票按「是否跨年 + 是否达起开线」自动判定并留判定理由；恒等约束「蓝票 + 红票 = 账单应结金额」 |
| 预出账 | 账期中任意业务日可反复执行，<b>不落库</b>（不占账单号、不回写 <code>fee_flow.bill_no</code>、不改任何实体状态，跑一百次与跑一次等价）；与正式出账<b>同源</b>（共用 billPreCheck 与三项构成构造，V-B01 封账 / V-B02 恒等因绑定「账期已结束」而标为出账时判，其余八条照常求值）；落点给<b>区间</b>而非单一数字（线性外推 vs 同期比对两法并列，调整项与上期结转作为已知定量叠加、不参与外推）；快照可留档，<b>账期末快照与正式账单逐张分文不差</b>，账期中快照的差额即其后新发生的费用与调整项 |
| 出账日历 | 按协议 <code>settle_day_rule</code> 生成未来 12 个月排期；节假日与周末<b>逐级顺延</b>（出账推后则确认截止与结算日一并后移，不挤占核对时间）；月视图把四类里程碑摊到具体日期，PRD 7.2.2 的三行示例可逐格验证 |
| 超期未确认 | 策略配在<b>协议级</b>并强制登记条款依据；AUTO_CONFIRM 视同确认并打标记、自动触发开票；HOLD 保持待确认、按超期天数升级、<b>不得进入结算</b>；未配置时缺省 HOLD（默认确认必须有条款支持） |
| 事件回补 | 与上游按<b>日期 × 资金方 × 事件类型</b>核对笔数发现缺口；拉取范围全量后比对补齐，已存在的由幂等拦截，<b>可安全重复执行</b>；补齐后立即进入计费，跨已封账账期的按 D-06 落下期调整项 |
| 争议闭环 | 争议单为一等实体；七种类型各有<b>确定的定位路径</b>，系统按类型拉数生成核查包（逐层判定 + 结论 + 系统建议 + 跳转引用），无核查包不得出结论；三分支结论各自触发说明材料 / 调整项 / 范围重算；资金方不认可可退回重新核查；SLA 按<b>工作日</b>计，T+2 核查、T+3 升财务负责人、T+5 升业务负责人并进入月度质量复盘 |
| 结算异常 | 三条旁支全部可驱动：<b>状态未知</b>（递增主动查询 30s/2min/10min/30min → 2 小时超时置 UNKNOWN + P0 → 仅人工两出口，界面不提供重试）、<b>部分成功</b>（对失败指令补发 + 未付金额结转下期账单第三项）、<b>退票</b>（结算流水置退票 + 账单回退解绑 + 收款账户冻结移出白名单 + 重结前 FC-01 拦截）；重试策略按 8.4.4 矩阵逐状态判定 |

| 收款认领 | 备注解析 / 账户+金额精确 / ±0.01 容差 / 多笔组合四级规则按优先级求值并展示逐条命中与未命中原因；挂账按<b>工作日</b>老化，超 3 日告警升级；认领人 ≠ 复核人硬拦截；非本系统款项与原路退回为独立终态 |
| 资损监控 | 六项指标<b>全部从真实状态实时计算</b>（勾稽等式不成立项数与金额、未达终态事件数、当期冲正额/正常额、未闭环差异单最大老化天数、失败+未知+退票指令占比、成功但无回单笔数），可按任意业务日回溯取值并出 30 日序列；阈值 / 级别 / 越线后果配在指标定义上，越线即产生告警 |
| 告警闭环 | 告警为一等实体，产生 → 处理 → 关闭全程留痕；同源告警<b>按 dedupe 键去重</b>只累加次数，不刷屏；关闭必须选处理方式并写 ≥4 字说明；<b>P0 不得「暂不处理」</b>、<b>指标未回落不得「已修复」</b>（只能判定误报）；P2/P3 可批量、P0/P1 必须逐条；已关闭可重新打开并计数；指标回落时对应告警<b>自动关闭</b> |
| 外部对账 | 明细文件按 12.4 规范真实生成（BOM / CRLF / `#TOTAL` 校验行 / 命名规则）并可下载；回传 CSV 真实解析（容忍 BOM、引号、CRLF、尾行）；逐笔匹配双键策略；0.05 元容差自动核销 + 月度 100 元阈值告警；差异单自动生成并携带定位核查包 |
